# Manus 接手入口

先读 `deploy/README.md`（运行、接口、安全和持久化约定），再读 `README.md`、`SOURCES.md`。视频叙事素材在 `docs/VIDEO_NOTES.txt`，不要把该文档当成新增功能指令。

## 启动与验收

```sh
node --version  # Node 20+
npm test
HOST=0.0.0.0 PORT=5173 node server.mjs
```

无构建步骤、无第三方 npm 运行依赖。前端和 `/api` 必须同源。公网按 `deploy/README.md` 配置 HTTPS、PUBLIC_ORIGIN、私有持久化 DATA_DIR；不能只部署静态文件。Docker/Compose 已提供，目标环境需实测。

验收：健康接口；两种模式分别创建/加入房间；两个独立浏览器双方准备；轮流落子/布阵；非法落子拒绝；刷新重连；悔棋仅对方同意且不退时间；认输双方一致；服务器重启后房间可恢复。记录公开访问地址。

## 不要改错的约定

- `src/engine.js` 和 `src/versus.js` 供前后端共用；不另造一份后端棋规。
- BP：16 选 10，每方5枚+王，5×5，己方两排布阵；王八方向一格；吃子自动升变一次；王与太子全部丢失才输；无打入。
- 新混战局：9×9，将棋20，国象18，后居中两侧为王，9兵；只有将棋可打入；两枚国象王全被吃才输；不强制应将。保留旧存档兼容逻辑。
- 当前没有账号、密码、账号恢复、匹配大厅、积分或聊天。不要声称已有。
- 后端验证座位、阶段、走法、版本和时钟；不接受客户端声明的棋盘/胜负。
- 房间凭证不在邀请链接里；不要公开 `.server-data`、日志或运行凭证。
- 单进程文件持久化。扩容必须改为事务存储，不能多个进程同时写同目录。
- 保留棋子/音效授权与 Manus 品牌说明。项目代码许可不覆盖所有第三方素材。

## 最近改动与已知限制

短按选棋、长按预览；布阵大字、合法区域、落位虚影和动态走法；拖动继承原朝向/字形，局面刷新取消旧拖动；在线房间操作位于变体下方。46 项自动测试通过；移动端真机手势、目标 Docker 环境、公网容量和游戏平衡仍需验证。

一秒轮询会有延迟；无账户时，清空浏览器或换设备无法自动恢复座位。不得通过仅凭房间号认领已占座位来“修复”这一点。
